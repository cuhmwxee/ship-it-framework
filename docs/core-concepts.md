# Core Concepts

## Input

Any work entering the framework.

Examples:

- Feature request
- Production bug
- Security issue
- Technical debt
- Documentation update

Input does not define priority.

Input simply identifies work.

---

## Development

The activity of producing or modifying software.

Development may be performed by:

- A developer
- Multiple developers
- Pair programming
- AI
- Any combination

---

## Validation

Validation provides independent verification that work is ready to ship.

---

## Ship

Making validated work available to its intended users.

How software is shipped is implementation detail.

# Terminology

This document defines the canonical language of the Ship It! framework.

---

## Normative terms

These terms define the framework.

- Input
- Development
- Validation
- Ship

Do not replace these with synonyms in normative documents.

---

## Informative language

Marketing copy, website content and reflection statements may use different wording.

Example

Framework terminology:

Development

Website slogan:

Build.

Both are valid within their respective contexts.

---

## Principles

Prefer one canonical term over multiple similar terms.

Do not introduce new terms unless they define a genuinely new concept.
